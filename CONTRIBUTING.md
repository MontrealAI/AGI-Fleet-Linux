# Contributing to AGI Fleet

Start with [development and exact-archive validation](docs/DEVELOPMENT.md). Work on a focused branch. Preserve existing modes, original acceptance rows, flowcharts, archived releases and evidence. Changes to the UI or guides need English/French consistency and actual user-path checks.

Canonical shared runtime is `fleet/shared/runtime/`. SUCCESSOR methods are canonical in AGIJobManager: update upstream, pin the exact commit and hashes, materialize all editions, refresh inventories, then rebuild the saved distribution. Do not edit a vendor copy while weakening provenance verification. Local Skills remains a separately qualified preview.

Before proposing a merge, reproduce the defect, retain negative results, run relevant regressions and complete all applicable exact-head native, integration, browser, archive and evidence-audit gates. A skipped or stale green result does not qualify new bytes. Do not clear STOP, reset consumed grants/spend journals, invent independent review or record unknown cost as zero. Do not use fixtures as live/provider/physical/usability evidence.

Changes to installers, authorization, signers, workflows, auditors and vendor boundaries require an eligible independent owner review. A separate eligible reviewer may use the shared MontrealAI GitHub account when explicitly authorized by the repository owner. Record the reviewer role, exact reviewed commit, findings, disposition and owner authorization in the PR. A COMMENT review under that account is a technical review record; GitHub does not allow that account to submit APPROVE on its own PR. Such a record does not prove separate GitHub identity or independently controlled economic review. Owner-authorized shared-account review may permit merge after the applicable checks pass. Distinct-account approval requirements apply only where actually configured; do not fabricate an APPROVED review or bypass an enforced rule. See [governance activation](docs/GOVERNANCE.md).
