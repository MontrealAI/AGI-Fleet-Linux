# Four-repository native computer compatibility

This additive engineering lane composes existing source APIs. Alpha's current
project-bound Computer Use handoff, journal, reservation, native worker and
signed return remain authoritative for their own semantics. Jobs' existing
supplier strategy engine supplies the frozen mission and recomputes actual
browser output. Separate Manager USDC and Jobs AGIALPHA adapters prepare
unfunded proposals. Alpha retains the complete handoff and native return with
human review still pending. Fleet's engineering runner coordinates this rehearsal;
it does not add a production browser backend to Fleet Local Skills.

The finite synthetic supplier case compares a single early supplier, split
delivery and bounded integer allocation. Its approved fixture formulation
retains ten units by day seven, forty by day fourteen and the original budget.
The actual frozen candidate is entered using real mouse/keyboard actions in
Chromium. A separate arithmetic implementation checks requirements and costs.
Scripted advice is disclosed throughout. This proves bounded actuator, receipt
and draft compatibility; it does not prove live model research quality,
protected evaluation, independently controlled economic review, realized savings
or paid commissioning.

Use exact clean checkouts selected in `compatibility-set.json`. The hosted
runner compares every imported source file against the selected HEAD Git blob,
rejects linked or untracked importable files, and checks the complete source
snapshot again after execution. Ignored interpreter caches are explicitly
excluded. The host dependency lock contains fourteen unmodified package blocks
from Alpha's existing hash-locked agent profile; installs require those hashes.
The hosted
workflow builds Alpha's existing reviewed Dockerfile, records the resolved base
image RepoDigest and local immutable image ID, and binds that image ID into the
native permit and signed receipt. Resolving a tag before recording its digest
does not establish cross-time reproducibility; retain the observed base digest
for an exact replay. There is no host fallback in the Docker command.
The source-kit ZIP packages the exact helper Git bytes and their compatibility
inputs; it requires the four source checkouts and is not a Fleet installer.
After the real browser result passes both native receivers, the same exact
drafts are exercised on two separate in-process chains with ID 31337. Jobs
uses its existing registry, a mock token and controlled validation; Manager
uses its existing escrow, a mock token and three controlled reviewer votes.
The positive paths observe actual mock-token payouts. Jobs' negative path
remains disputed with no worker payout; Manager's negative path returns escrow
to the mock buyer with no worker transfer. These local transactions and their
receipts qualify software mechanics only. No real asset or economic authority
is involved. `verify-evidence.mjs` rejects mixed projects, changed native returns,
different source pins, protocol doubles presented as browser evidence, or a
missing negative observation before producing the combined compatibility record.

An explicitly selected `--actuator host-laboratory --chromium-executable /path`
exists for development. Its native environment is labelled HOST LABORATORY and
its evidence sets `dockerIsolation: false`. It never qualifies the Docker lane.
The managed local execution environment currently refuses Chromium's Unix socket;
that observed failure is retained as an interrupted session, with no screenshots
or completed Computer Use claimed. Hosted execution must actually pass.

The local `operator-journal` contains a generated disposable test signing key.
Do not publish that directory. Workflow uploads use explicit public artifact
paths and never include journals. No real wallet, deployer key, provider credential,
transaction, funded admission, on-chain authority or ENS change is involved.
Provider/device cost and human minutes remain unknown; unknown values are null.
Preserve the Ubuntu Hardhat hidden ephemeral deployer-key route and Mac Studio
Ledger governance as separate operator workflows; previous deployments stay
read-only.
