# Reporting security concerns

For a suspected vulnerability, use GitHub's private **Report a vulnerability** feature if the repository administrator has enabled it. Do not put credentials, wallet material, private task content or exploit details in public issues. If private reporting is unavailable, request a private maintainer channel using a minimal public description without sensitive details. A private reporting route still requires administrator configuration; this file does not enable it.

Preserve the affected release identity, sanitized error code and evidence. Do not clear STOP, replay uncertain actions or discard authority/spend journals to reproduce an issue. Withdraw unsafe execution recommendations while keeping historical artifacts accessible and clearly labelled. Rotate affected credentials through supported provider/wallet controls; local deletion cannot revoke remote credentials or erase provider copies.
