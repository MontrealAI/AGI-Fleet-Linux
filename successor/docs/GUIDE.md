Create useful work first. Connect a prepared computer when you need it. Check improvements and keep the version you choose.

2. Choose **Understand my data** or **Make a website**. Edit the example and confirm your rights to use the public, licensed, synthetic, nonpersonal input.
3. Choose **Create & run my Ω**. Inspect the editable files and separate checks, then choose **Keep this version**.
4. **Build & check the improvement** compares a reviewed reusable method with the incumbent. The data method removes identical repeated IDs and rejects conflicting IDs. The website method adds keyboard-accessible section navigation. A tie or regression retains the incumbent. This is bounded software, not downloaded frontier-model weights.
5. Download the offline HTML, JSON capsule, readable summary and editable source. Open the HTML in a new desktop-browser context, inspect/import the capsule, confirm restore and rerun. Browser storage is optional and is not a private vault.

## Keep larger work safely

The original capsule stays capped at 4 MB. General Studio work remains capped at 64 files, 32 MiB each and 64 MiB total; smaller specification limits apply. Use a manifest-bound sidecar directory for larger results. The pack contains exact files, capsule, handoff and historical receipt, with sizes and SHA-256 identities. It contains no signing authority or provider secret.

```sh
node successor/cli.mjs export-pack capsule.json handoff.json receipt.json NEW_PACK
node successor/cli.mjs inspect-pack NEW_PACK
node successor/cli.mjs restore-pack NEW_PACK NEW_DIRECTORY
node successor/cli.mjs restore-pack NEW_PACK NEW_DIRECTORY --confirm
```

Inspection never executes imported code. Keep the entire directory together. Missing, extra, changed, linked or case-colliding files fail inspection. Interrupted exports use a temporary directory and do not overwrite a good export. Existing encrypted wallet backups remain separately bounded; explicitly exclude large Studio work only after exporting it. Wallet backup does not include `successor-execution` records or these portable sidecars. Export them separately.

A SUCCESSOR pack must belong to one project: its capsule retains the plan named by the handoff, its immutable mission inputs match that plan, and its receipt and every artifact match the delivered bytes. For the two local mission families, the artifacts must reproduce the incumbent or proposed reusable method. Custom public Studio work can retain larger, plan-bound artifacts as historical evidence; format and integrity checks do not make them a locally executable or qualified candidate. Keep arbitrary rejected work through Studio's existing handoff/receipt and file exports. A mismatched project, missing plan or altered reusable method blocks pack creation, inspection and restoration. The terminal `request` command records the plan in its new request capsule without changing the original file.

Un paquet SUCCESSOR doit conserver le plan de ce projet, les mêmes entrées immuables et les octets exacts du travail et du reçu. Un autre projet ou une méthode modifiée bloque l’exportation et la restauration. Les grandes pièces jointes d’une mission personnalisée restent des preuves historiques ; leur intégrité ne leur confère aucune qualification ni autorisation.

For custom public work, first save your custom mission and complete Studio v2 specification, then run:

```sh
node successor/cli.mjs prepare-custom mission.json studio-spec.json 100 NEW_PROJECT
```

This creates a new capsule and plan that commit to the entire specification, including input references, deliverables, requirements, criteria, runtime identities and limits. It preserves your original input description and parent reference; the new specification names the new plan as its parent. Review `NEW_PROJECT/specification.json`, import it into the existing public Studio, and separately authorize execution and review. Export with `NEW_PROJECT/capsule.json` and the resulting handoff and receipt. The amount is an explicit USDC planning allowance; preparation spends nothing. Original files stay unchanged. Changing the specification requires preparing a new project before execution. An older custom capsule without this binding can still use all existing Studio exports, but cannot claim a plan-bound SUCCESSOR pack.

Pour un travail public personnalisé, cette commande crée un nouveau projet qui conserve la spécification complète, les entrées, les livrables et leurs critères. Examinez `specification.json`, importez-le dans le Studio public existant, puis autorisez séparément l’exécution et la révision. Le montant est un budget de planification explicite en USDC ; aucune dépense n’est autorisée. Les fichiers originaux sont conservés. Une modification de la spécification exige un nouveau projet avant l’exécution.

## Guided connection and saved versions / Connexion guidée et versions

The installed panel can build the context for you. Import the Builder request and the reviewing Node's downloaded runtime file, download each exact immutable input, and enter its public HTTPS URL. Choose explicit provider time and cost limits, review the public-input permission, then inspect. Existing Agent deployment settings provide the specification's settlement identity. No payment or on-chain submission occurs. Advanced operators can still import a complete context JSON.

Le panneau installé prépare le contexte à partir de votre demande et du descripteur fourni par le Node de revue. Téléchargez les entrées exactes, indiquez leurs URL HTTPS publiques et choisissez les limites explicites. Vérifiez les droits des données, puis examinez le travail. L’identité de règlement vient de la configuration existante ; aucun paiement ni envoi sur chaîne n’est effectué.

After restoring a returned capsule, use **Inspect a saved version** in Results to inspect a candidate. This changes only the view. **Keep this version** is the separate selection action; a tie or regression keeps the incumbent. Rollback restores a previously chosen local version and does not undo external effects.

Après restauration, **Examiner une version conservée** affiche le candidat sans l’activer. **Conserver cette version** reste une décision distincte. Une égalité ou une régression conserve la version actuelle. Le retour à une version précédente n’annule pas les effets externes.

The terminal execution commands acquire the same exclusive `application.lock` as the installed app. Close the app before terminal execution; never delete an active profile lock to force entry. The normal launcher owns stale-lock recovery.

## Terminal workflow / Parcours terminal

Run these commands from the extracted Fleet directory with the bundled Node version. Each new output must not already exist. Start locally without a wallet or provider:

```sh
node successor/cli.mjs example analyst mission.json
node successor/cli.mjs run mission.json baseline.json
node successor/cli.mjs choose baseline.json latest selected.json
node successor/cli.mjs validate selected.json
node successor/cli.mjs inspect selected.json
node successor/cli.mjs plan selected.json 100 plan.json
node successor/cli.mjs request selected.json plan.json request.json
node successor/cli.mjs inspect-request request.json
node successor/cli.mjs compile-request request.json context.json compiled.json
```

`context.json` must contain the actual runtime descriptors and permitted immutable input URLs described above. The budget is a planning commitment, not permission to fund a job. With existing configured Agent and Node profiles, substitute their absolute profile paths below. Execution and review ask for the hidden local vault password and the complete displayed specification hash. The result files contain the actual handoff and receipt, so no browser is needed:

```sh
node successor/cli.mjs execute agent /absolute/agent-profile request.json context.json agent-result.json
node successor/cli.mjs review node /absolute/node-profile agent-result.json node-result.json
node successor/cli.mjs check-result request.json agent-result.json node-result.json checked.json
node successor/cli.mjs inspect checked.json
node successor/cli.mjs compare checked.json CANDIDATE_HASH
node successor/cli.mjs choose checked.json CANDIDATE_HASH chosen.json
node successor/cli.mjs export chosen.json NEW_OFFLINE_DIRECTORY
node successor/cli.mjs export-pack chosen.json agent-result.json node-result.json NEW_PACK
node successor/cli.mjs restore-pack NEW_PACK NEW_RESTORE_DIRECTORY --confirm
node successor/cli.mjs restore chosen.json --confirm restored.json
node successor/cli.mjs improve restored.json rerun.json
node successor/cli.mjs rollback chosen.json INCUMBENT_HASH rolled-back.json
```

Use the candidate hashes from inspection or the checked result. `check-result` reports rejection without changing the incumbent; comparison does not select a version. `improve` above reruns the supported deterministic local engine and grants no Fleet authority. To recover an output after a failed download or terminal disconnect, use `result agent|node ABSOLUTE_PROFILE ATTEMPT_KEY NEW_RESULT` with the saved attempt key; it never redispatches work. `stop agent|node ABSOLUTE_PROFILE` revokes pending work in that opened profile. For an already running application or terminal that owns the profile lock, use its existing Stop work control or the installed `Stop-Compute.sh`; never bypass the lock. Errors include a stable code and leave previous exports intact.

Le parcours terminal utilise les mêmes contrôles que l’application. Les fichiers de résultat contiennent le travail réel et le reçu de revue. La comparaison n’active rien : choisissez explicitement une version. Une restauration ne réactive ni mot de passe, ni autorisation historique. Les commandes d’exécution demandent une confirmation locale ; ne contournez jamais le verrou d’un profil actif.
