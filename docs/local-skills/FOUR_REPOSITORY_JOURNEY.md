# One project through Alpha, Jobs, Fleet and Manager

This guide describes the alpha.6 source candidate. Its new browser route must
pass the exact saved-package service and browser gates before publication.
Use the same reviewed compatible versions at every step. The published
alpha.5 CSV journey remains in [its own guide](PROJECT_JOURNEY.md).

Use only public, non-personal material. The optional Fleet route is a bounded
scripted browser rehearsal with zero model-provider requests and zero provider
cost. Device time, operator effort and independent economic review remain
unmeasured. The pages prepare files and unsigned proposals; they grant no wallet,
payment or on-chain authority.

The [release guide's cost scopes](DOWNLOAD_ALPHA_6.md#reading-the-cost-observations)
separate zero scripted-provider cost, unknown human/device costs, nine
conceptual service-only CLI alternative commands, separately recorded automated
dashboard controls and differently scoped mock-chain gas. They do not
claim savings or a cost advantage.

## Prepare and freeze the mission

1. In Alpha's mission form, name the capability, state the opportunity, who
   benefits and what a useful deliverable must achieve. Supply the public
   context and work surface, then examine **Improve the strategy. Challenge
   the frame.** Review the competing strategies, their combination and any
   proposed change to the problem. Choose **Prepare my capability mission**,
   then **Save my complete workspace** or **Download complete project archive**.
   Preparation adds an unexecuted attempt; it does not run the task. Preserve
   the existing working version until you deliberately accept an improvement.
2. In Jobs, choose **Construct, freeze and test methods**. Read the requirements,
   costs and deadline checks. If comparing a different formulation, supply the
   requested owner label and reason and explicitly approve that local
   comparison. The actual requirements remain unchanged; approval grants no
   purchasing or execution authority.
3. Under **Continue your Alpha project through Computer Use**, select the saved
   Alpha workspace and frozen strategy report. Review the project, strategy and
   exact mission, confirm public inputs, then prepare the native handoff.
   Download **native handoff for Fleet** and **its exact frozen report**. Keep
   those exact files together. This supplier handoff fits Fleet's 90-second,
   30-action and eight-turn rehearsal bounds.

Alpha's general Computer Use form also permits native handoffs. For Fleet,
open **03 · Execution setup and advanced controls** and set maximum seconds
to 120 or less before preparing one. Fleet also caps actions at 30 and turns
at 10. A supported handoff alone does not install or authorize an executor.

## Run under your exact local grant

An operator must first install the [reviewed private Fleet profile](../../local-runtime/computer/README.md)
and start the local service. This setup currently uses the operator CLI.
The profile binds this exact handoff, reviewed fixed actions, source checkout,
physical Python environment and immutable Docker image. A different handoff or
action sequence needs a new reviewed profile and fresh activation and grants.
The browser does not choose providers, executable code or action scripts.

1. Connect using the launcher's local credential. It is cleared from the masked
   field and held only in page memory. Check readiness and select an active
   Agent.
2. Under **Use your Alpha project in a browser**, upload the exact handoff and
   confirm public, non-personal inputs. **Prepare** creates no execution
   authority. Read the displayed handoff, installation identity and limits.
3. Choose **Authorize this exact run**, then **Run on this computer**. The grant
   is for one use. **STOP all actors** requests cancellation and blocks new
   work. An interrupted attempt remains in history; recovery requires explicit
   reconciliation, fresh activation and a new exact grant.
4. Choose **View output** for the recorded run. Save **native return for Alpha**
   and its screenshots. The dashboard checks retained byte lengths and hashes.
   Retained interrupted and reconciled artifacts remain read-only exports and
   are labelled incomplete. Their export does not declare success.

Import the native return into the **same** Alpha project with **Import Computer
Use result**. Review each acceptance condition and keep your review with that
attempt. A scripted completion or an imported checksum does not supply
independent acceptance. Save the complete Alpha workspace again so its earlier
work, reviews and failed attempts travel with the project.

## Propose one explicit asset and keep the whole history

For **USDC**, open Manager's Computer Use receiver. Supply the exact handoff,
native return, frozen Jobs report and complete Alpha workspace archive. Enter
the proposed amount, review the displayed Ethereum mainnet network, token and
six-decimal units, confirm public inputs and prepare the unsigned proposal.
This chooses no deployment, reserves zero funds and creates no transaction.
Download the complete Manager project history; optional browser storage can be
cleared or reach its quota. Reopen that full history before appending another
proposal for the same project. A stale tab or shorter replacement cannot
overwrite earlier saved proposals.

For **AGIALPHA**, use Jobs' returned-work panel with the same exact files and
complete Alpha workspace. Explicitly choose the proposal network and amount
with at most 18 decimals. Check the return and prepare the unfunded draft, then
save **project, history and draft**. Reopen that Jobs workspace to continue it.
The two asset routes have separate archives and native receivers; there is no
automatic asset conversion or cross-route archive restoration.

Keep the complete route archive before closing or moving devices. In Manager,
**Download the original complete Alpha workspace** preserves the whole supplied
Alpha file byte for byte; **Download native history for the same Alpha project**
also carries the newly retained attempts. To reopen Alpha elsewhere, restore
the original complete workspace first, then import the latest native history
into that same project. Earlier work and the incumbent remain retained until
you deliberately choose otherwise. If no complete Alpha file was supplied,
the receiver cannot reconstruct missing earlier work or owner reviews.

Live deployment, signing, funding, activation of paid work and on-chain
authority changes require separate authorization. Ubuntu Hardhat's local,
hidden ephemeral deployer-key entry and Mac Studio Ledger governance remain
separate operator routes. Previous deployments remain read-only. ENS work is
outside this assessment.

## Français

Ce guide décrit le candidat source alpha.6. Son parcours installé doit réussir
les contrôles exacts de paquet, service et navigateur avant publication. Le
[parcours CSV alpha.5 publié](PROJECT_JOURNEY.md#français) reste distinct.
Utilisez seulement des données publiques non personnelles. La répétition
scénarisée ne fait aucune requête à un fournisseur de modèles; son coût
fournisseur est nul. Les coûts humains et matériels restent non mesurés.
Les [périmètres du guide de publication](DOWNLOAD_ALPHA_6.md#français)
distinguent les neuf commandes conceptuelles de l’autre parcours CLI du service,
les contrôles d’interface automatisés et les reçus de gaz simulé des deux routes. Ils ne prouvent ni
économies ni avantage de coût.

1. Dans le formulaire de mission [Alpha](https://montrealai.github.io/AGI-Alpha-Agent-v0/successor/alpha/),
   nommez la capacité, décrivez l'occasion, son bénéficiaire et les critères
   d'un résultat utile. Fournissez le contexte public et la surface de travail;
   examinez les stratégies concurrentes, leur combinaison et tout nouveau
   cadrage proposé. Préparez la mission, puis enregistrez l'espace complet ou
   l'archive complète du projet. Cette préparation conserve une tentative non
   exécutée et ne lance aucun travail. Conservez la version de travail jusqu'à
   votre choix explicite d'une amélioration.
2. Dans le [laboratoire Jobs](https://montrealai.github.io/AGIJobsv0/successor/computer/fr/),
   choisissez **Composer, figer et tester les méthodes**. Une autre formulation
   exige le nom du responsable, sa raison et une approbation explicite de la
   comparaison locale; les exigences réelles restent inchangées. Importez le
   même espace Alpha et le rapport figé dans le panneau Computer Use,
   examinez-les, puis téléchargez la transmission native pour Fleet et son
   rapport figé exact.
3. Un opérateur installe d'abord le [profil privé exact](../../local-runtime/computer/README.md)
   avec la CLI et démarre le service local. La transmission, les actions fixes,
   les sources et l'image Docker sont liés à ce profil. Une nouvelle
   transmission exige un nouveau profil examiné et des autorisations fraîches.
4. Dans le tableau de bord Fleet local authentifié, vérifiez la disponibilité
   et choisissez un Agent actif. Sous **Utiliser votre projet Alpha dans un
   navigateur**, importez la transmission exacte et confirmez les données
   publiques. Préparez, examinez, autorisez cette exécution précise et exécutez
   une seule fois. L'**ARRÊT** bloque les nouveaux travaux et demande
   l'interruption. La reprise ne rejoue pas l'ancienne autorisation.
5. Choisissez **Voir le résultat**, puis enregistrez le retour natif pour Alpha
   et les captures. Les longueurs et empreintes sont vérifiées. Les preuves
   interrompues ou réconciliées restent exportables en lecture seule, sans
   déclaration de réussite. Importez le retour dans le même projet Alpha,
   examinez ses critères et enregistrez à nouveau l'espace complet.
6. Pour **USDC**, ouvrez le [récepteur Manager](https://montrealai.github.io/AGIJobManager/fr/computer-receipt/).
   Fournissez la transmission, le retour, le rapport Jobs et l'archive Alpha
   complète. Examinez le réseau Ethereum, le jeton et les six décimales;
   proposez un montant explicite et téléchargez l'historique Manager complet.
   Pour **AGIALPHA**, utilisez le panneau de retour Jobs, choisissez
   explicitement le réseau et le montant, avec au plus 18 décimales, puis
   enregistrez le projet, l'historique et le brouillon. Ces archives de routes
   restent distinctes, sans conversion automatique.
7. Rouvrez l'historique complet de la même route avant d'ajouter une
   proposition. Conservez les téléchargements avant de fermer ou de changer
   d'appareil. Dans Manager, téléchargez l'espace Alpha complet original et le
   dernier historique natif; restaurez d'abord l'espace original dans Alpha,
   puis importez l'historique natif dans ce même projet. Les tentatives,
   examens et octets originaux fournis sont conservés; les éléments absents ne
   peuvent pas être inventés.

La transmission fournisseur utilise 90 secondes, 30 actions et huit tours.
Pour un autre formulaire Alpha, réglez les contrôles avancés à 120 secondes
maximum, 30 actions et dix tours avant de préparer la demande Fleet. Les
propositions restent non signées et non financées, sans portefeuille ni
autorité. Déploiement réel, signature, financement, travail payant et changement
d'autorité exigent une autorisation distincte. Les clés Hardhat Ubuntu restent
locales, masquées et éphémères; la gouvernance Ledger sur Mac Studio reste
séparée. Les anciens déploiements sont en lecture seule et ENS reste hors de
cette évaluation.
