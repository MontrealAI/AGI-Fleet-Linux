# Install and recover / Installer et reprendre

These tools install the separately labeled development preview. They are not a production-qualified operator installer. Start with the [download and verification guide](DOWNLOAD.md). The package must come from the exact reviewed source and have a verified SHA-256. An archive checksum establishes identity, not correctness or authorization. Existing Dedicated Fleet installations use their existing installers.

## English

The installer does not need administrator privileges and does not start a service, activate an actor, connect a provider, install a skill in an assistant, or handle a wallet. Keep the application directory and private state directory separate and outside the source checkout. It accepts only the platform's existing pinned Node 24.21.0 archive; see `fleet/shared/runtime/compute/runtime-artifacts.lock.json`. Linux execution additionally needs the documented supported bubblewrap environment. Copying code on a Mac does not qualify a Mac execution backend.

Use an inspected local package and the exact expected digest, not a digest taken from an untrusted neighboring file:

```sh
python3 local-runtime/install.py inspect --archive /absolute/package.zip --sha256 EXPECTED_SHA256
python3 local-runtime/install.py install --archive /absolute/package.zip --sha256 EXPECTED_SHA256 --node-archive /absolute/node-v24.21.0-linux-x64.tar.xz --root /absolute/fleet-application --state /absolute/fleet-private-state --confirm
python3 local-runtime/install.py launch --root /absolute/fleet-application -- init
python3 local-runtime/install.py launch --root /absolute/fleet-application -- serve
```

The launcher reports the local dashboard address and private credential **file**, never the credential itself. Paste that credential into the local dashboard only. Create and activate an actor, inspect a prepared task, authorize its exact grant, then run. Each additional actor shares the read-only installation without another download.

To maintain software, stop intake and finish or reconcile work, then stop the supervisor. `update` uses the same arguments as `install` with a new package/digest. Old verified versions remain available. `rollback --root /absolute/fleet-application --version PREVIOUS_ARCHIVE_SHA256 --confirm` selects code only. It does not restore credentials, budgets, revocations or consumed grants; changed source requires fresh bindings. `uninstall --root /absolute/fleet-application --confirm` removes only verified owned code. It refuses extra files, active service sockets, pending grants and uncertain runs. Private state and external outputs remain available. Archive packaging, Node binaries and every installed file/mode are verified; arbitrary archives are not imported as state.

If the service was killed, stop its launcher and inspect the process situation. `launch --root /absolute/fleet-application -- recover-service --confirm` refuses a live service or lock holder. For a dead service it may remove only the same private, owned, positively stale socket, persists STOP, revokes unused grants and deactivates actors. Recovery holds the private control socket throughout its authority reset, excluding concurrent direct CLI starts. A failed bind changes no authority, and a storage fault releases the temporary endpoint. Interrupted work stays uncertain. It never kills an unknown process or assumes that missing connectivity proves cleanup.

Restart `serve`, inspect each uncertain attempt and select **Inspect recovery**. Reconciliation is available only for the offline sandbox with recorded process/namespace closure, or an observed different boot identity. Missing proof stays blocked. Explicitly close the attempt **without success**, retaining its evidence and reservation. Then separately resume and activate again. Paid/provider/signer attempts cannot be cleared by this offline procedure.

During a failed stage or atomic pointer switch, the previous complete version remains selected. Maintenance atomically reserves the CLI socket path with a private marker, so even a raw CLI launch cannot start work during an update. A crash can leave this marker, an unselected staging directory or a stale maintenance lock. `recover-maintenance --root /absolute/fleet-application --confirm` releases only a recognized marker/lock whose process has ended or whose recorded boot has changed. It refuses a real service socket, then requires `recover-service --confirm` before restart. Do not delete unrecognized content; leftover stage content requires operator inspection and is deliberately not included in automatic uninstall. A fresh installation also writes a durable pre-install journal before taking either fence. If it dies before `installation.json` exists, `recover-maintenance` verifies the original private root/state directory identities and dead owner, then permits the same `install` command with the same archive digest. It never resumes execution, recreates state or removes unknown files. A complete version renamed before the pointer commit is reused only after full verification. Unselected staging remains preserved; removal still refuses unknown content. If the pointer was committed, recovery clears only the matching journal and maintenance markers. Live owners, changed directories, different archives and nonempty fresh state remain blocked. The crash tests terminate the installer process at four boundaries; they do not establish power-loss or physical reboot qualification.

## Français

Cet outil installe l’aperçu de développement distinct, sans qualification pour la production. Commencez par le [guide de téléchargement et de vérification](DOWNLOAD.md#français). Il vérifie le paquet et l’archive Node 24.21.0 correspondant à la plateforme. Il n’exige pas de privilèges administratifs, n’active aucun acteur, ne démarre aucun service et ne connecte ni fournisseur ni portefeuille. Gardez les répertoires d’application et d’état privé distincts, hors du code source. Les commandes ci-dessus utilisent des chemins absolus. Sur Linux, l’isolation bubblewrap prise en charge reste nécessaire; une copie sur Mac ne qualifie pas l’exécution macOS.

Après `install`, exécutez séparément `init`, puis `serve`. Le lanceur indique l’adresse locale et le fichier d’identifiant privé. Collez l’identifiant uniquement dans le tableau de bord local. Ajoutez un acteur, activez-le, examinez les données et limites de la tâche, autorisez cette exécution précise, puis lancez-la. Ajouter un rôle ne télécharge pas une autre installation.

Avant une mise à jour ou suppression, suspendez l’entrée de travaux, terminez ou réconciliez les obligations et arrêtez le service. `update` reprend les paramètres d’`install` avec un nouveau paquet. `rollback` sélectionne une version de code vérifiée, sans restaurer les anciennes autorisations ni réinitialiser les budgets. `uninstall` refuse les contenus inconnus et les obligations inachevées; il conserve l’état privé et les résultats externes.

Après un arrêt brutal, `recover-service --confirm` refuse un service encore actif. La reprise d’un service mort conserve l’ARRÊT, invalide les autorisations inutilisées et désactive les acteurs. Pendant cette remise à zéro des autorisations, la reprise réserve le socket privé et exclut tout lancement CLI concurrent. Un échec de réservation ne modifie aucune autorisation. Les travaux interrompus restent incertains. Redémarrez le service, examinez chaque tentative et choisissez **Examiner la reprise**. Seule une fermeture observée du bac à sable hors ligne, ou un redémarrage du système effectivement observé, permet de clore la tentative sans réussite. Les preuves et réservations sont conservées. La reprise, l’activation et les nouvelles autorisations restent des décisions séparées. Ce parcours ne réconcilie jamais un paiement, une signature ou une requête fournisseur.

Pendant la maintenance, le chemin de connexion du service est réservé pour empêcher aussi un lancement direct par CLI. Une interruption peut laisser cette réservation ou un dossier temporaire non sélectionné. `recover-maintenance --root /absolute/fleet-application --confirm` ne libère qu’une réservation reconnue dont le processus est terminé ou dont le système a redémarré; exécutez ensuite `recover-service --confirm`. Le code précédemment sélectionné reste complet. Inspectez les contenus inconnus; aucune suppression large n’est effectuée. La qualification après panne d’alimentation et sur matériel physique reste à réaliser.

Une première installation écrit aussi un journal durable avant ses réservations. Si elle est interrompue avant `installation.json`, la reprise vérifie les identités des répertoires privés et la fin du processus, puis permet de répéter exactement la commande `install` avec le même paquet. Aucun état ni contenu inconnu n’est supprimé, et aucun travail ne reprend automatiquement. Une version complète déjà copiée est intégralement vérifiée avant réutilisation. Un propriétaire actif, un répertoire remplacé, un autre paquet ou un état initial non vide bloque la reprise. Les essais tuent le processus à quatre étapes; ils ne prouvent pas une reprise après panne électrique réelle.

## Read-only prerequisite inspection / Inspection sans modification

Before installation, run the following command with the same reviewed archive, digest, pinned platform Node archive and intended paths as `install`:

```sh
python3 local-runtime/install.py preflight --archive /absolute/package.zip --sha256 EXPECTED_SHA256 --node-archive /absolute/node-v24.21.0-linux-x64.tar.xz --root /absolute/fleet-application --state /absolute/fleet-private-state
```

For an existing installation add `--for-update`. This inspection creates no directories, locks, credentials or services, and executes no package or runtime binary. Its machine-readable report identifies missing or changed archive identity, platform, Node identity, private path prerequisites, staging capacity, trusted `/usr/bin/bwrap` and `/usr/bin/prlimit`, and visible namespace policy restrictions. Installing those distribution prerequisites may need an administrator; the Fleet installer itself runs as the standard compute user. The staging estimate is an observation, not reserved capacity. A present prerequisite does not establish working isolation: run installed `doctor`, then fresh task admission. Credentials, provider access and native execution are not observed by preflight. Mac execution remains unimplemented. A blocked report preserves user files and explains the next step; `readyForInstallInspection` is the field to inspect, not merely the command's successful report generation.

Cette commande ne crée aucun répertoire, verrou, identifiant ou service et n’exécute aucun binaire du paquet. Ajoutez `--for-update` pour inspecter une mise à jour. Le rapport distingue l’identité des archives, les chemins, la capacité de stockage et les prérequis d’isolation. Seule l’installation des prérequis de la distribution peut demander un administrateur; Fleet s’exécute sous le compte de calcul standard. Cette inspection ne réserve pas d’espace et ne qualifie pas l’exécution. Exécutez ensuite `doctor` et une nouvelle admission de tâche. Les fournisseurs et l’exécution Mac restent non observés ou bloqués selon leur statut existant.

## Interrupted removal / Suppression interrompue

Removal now commits `pending-removal.json` before deleting any verified code member. The journal binds the original private installation/state directories and each owned member's path, identity, mode and digest. While it exists, launch/update/rollback are blocked. If removal is interrupted, use `recover-maintenance --root /absolute/fleet-application --confirm`, then repeat `uninstall --root /absolute/fleet-application --confirm`. Recovery refuses a live owner, changed directory/member, unknown added file or real service socket. Retry accepts only already absent journaled members and removes the remaining unchanged owned code; it never removes the external state directory, credentials, journals, reservations or outputs. The journal permits continuing removal, not restoring a partially deleted software version. Final cleanup first atomically commits a private sibling `<installation>.removal.json` completion receipt. It binds the original root, parent and preserved state identities; repeating uninstall or recovery can finish an empty root or remove its completed receipt. Descriptor-relative deletion rechecks parent/member identity and digest, so a replaced parent symlink is refused without deleting its target. A process killed while preparing the atomic receipt may leave a private `.agi-fleet-removal-*.tmp` file in the installation parent; it carries no authority and is preserved for explicit operator inspection. The valid pending-removal journal remains resumable. Do not broadly delete unknown temporary files. Process-exit regression fixtures cover the committed journal, partial member deletion, deleted version directories and final-root boundaries; physical reboot, sleep and power-loss qualification remain NOT_RUN.

La suppression écrit d’abord un journal durable des seuls éléments de code vérifiés. Si elle est interrompue, utilisez `recover-maintenance`, puis répétez `uninstall` avec le même répertoire. Toute exécution, mise à jour ou sélection de version reste bloquée pendant cette suppression. La reprise refuse un propriétaire actif, un élément modifié ou un fichier inconnu. Elle conserve toujours l’état privé, les identifiants, les réservations et les résultats. Elle poursuit la suppression; elle ne restaure pas une version de code partiellement effacée. Les essais couvrent l’arrêt du processus, sans prétendre qualifier les coupures de courant physiques.

Cross-host restore remains an **inactive profile/project import**, with no grant, client, signer or budget authority restored. An authoritative two-host execution fence is still unimplemented; exporting and restoring work does not qualify clone activation. Existing Dedicated Fleet installation and recovery controls are unchanged.

## Local project history / Historique des projets locaux

An operator can import/export a full project even at 100 history events. Restore preserves the exact inactive state. Before continuation, call `project-export`, save its exact `capsule` string as a checkpoint, and calculate SHA-256 over those UTF-8 bytes without adding a newline. Then submit a private `project-continue-history` request containing `project` (the returned UUID), `checkpointSha256` and `confirm: true`. The server refuses stale checkpoints and concurrent changes. It retains all prior events in an archive, opens a new segment and returns capacity; it grants no run permission. This operation belongs only to the operator, outside the six assistant actions. The existing CLI supports `request project-continue-history /absolute/private-continuation.json`. Use the updated Builder to open archival capsules. Finite bounds and candidate/plan capacity remain the same as the [practical guide](../../successor/docs/PRACTICAL_QUALIFICATION.md#keep-working-when-history-fills).

**Français.** L’opérateur peut importer et exporter le projet même à 100 événements. Enregistrez d’abord les octets UTF-8 exacts du champ `capsule` de `project-export`, sans saut de ligne ajouté, et calculez leur SHA-256. Une demande privée `project-continue-history` contient le UUID `project`, cette empreinte `checkpointSha256` et `confirm: true`. Une empreinte périmée ou une modification concurrente est refusée. Les anciens événements restent archivés; aucune permission d’exécution n’est accordée.
