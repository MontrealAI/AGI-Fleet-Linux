## What you can evaluate now

On a supported Linux engineering host, one installation can hold several isolated actor profiles. The implemented path produces a deterministic public-data report, checks its exact bytes, and preserves a separately authorized internal review and an explicit SUCCESSOR version choice. Six lightweight skills use the existing role boundaries. The specialist economic roles inspect policy; they do not sign or submit transactions.

The transactional development installer preserves private state and user outputs during update, software rollback, recovery and removal. The pinned OpenClaw adapter uses private IPC, actor-specific credentials and a separate operator approval. These are implemented behaviors with bounded engineering evidence, not a completed browser/desktop workforce.

The new [capability admission contract](CAPABILITY_ADMISSION.md) checks an exact task without creating authority, records supported operations and limits in its grant, and rechecks bound configuration before authorization and dispatch. It distinguishes supportable work, missing prerequisites and unsupported scope; custom missions are refused before reservation. Its component tests do not qualify general tools, live providers, independent review or Mac local execution, and the original 22 acceptance requirements remain in force.

For help, use **Preview support report** in the local dashboard, inspect its complete contents, and choose **Save this report**. Only readiness and aggregate counts are included. Credentials, actor names/identities, host identifiers, paths, tasks, outputs and event history are excluded. Nothing is uploaded automatically. A passing readiness probe does not commission the machine.

## Preservation and validation

The inherited Fleet workflow can now be called as a reusable validation workflow. All existing build, native, integration, browser and audit gates remain mandatory; validation-only reuse disables its publisher. Dedicated Fleet publication triggers and qualification are otherwise unchanged. Per-commit PR qualification and uncancelled publication locks remain intact.

The maintenance regression formerly asserted that `local-runtime/` could not exist anywhere in the repository. That assertion conflicts with this explicitly additive mode. The replacement checks the actual Fleet source inventory and adds a build-time check of the **saved Linux 1.1.1 ZIP**, rejecting `local-runtime`, `local-dashboard` or `role-skills` at any depth. Negative fixtures require rejection of embedded development code; ordinary guidance may explain the separate mode. This preserves the release exclusion without forbidding unrelated source development. The [preservation report](integration-preservation.json) records the engineering changes, Mac source-inventory synchronization, reusable-workflow addition and documentation discovery links.

Local verification passed 120 engineering tests and the support-report privacy/authorization and reconciliation cases. The full local supervisor run retains four failures caused by this workspace denying Unix-socket listening (`EPERM`); no test was skipped or weakened. The pinned browser download was unavailable here. Native IPC and EN/FR download/accessibility behavior therefore remain mandatory CI gates, including tests from the exact saved package.
