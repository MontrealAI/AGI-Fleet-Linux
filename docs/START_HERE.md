## Installing? Follow this order

1. **Choose the platform guide first.** Follow it in order on a clean, supported computer. Keep signer and compute accounts separate. Do not mix Linux commands with Mac commands or combine instructions from different versions.
2. **Download the installer asset, not GitHub's “Source code” archive.** For Linux, obtain `AGI_Fleet_Linux_v1.1.2.zip` and `SHA256SUMS-v1.1.2.txt` from the [same release](https://github.com/MontrealAI/AGI-Fleet-Linux/releases/tag/v1.1.2-qualification). Use the platform guide's verification and extraction instructions. A CI review-source ZIP is also not an installer.
3. **Complete readiness and record observations.** Use the [Linux qualification ledger](PHYSICAL_QUALIFICATION.md) or the Mac guide's platform-specific checklist. Published automated results do not prove that your machine, provider connection, desktop permissions or cleanup are ready.
4. **Keep funded work disabled while qualification remains open.** Use the public or synthetic inputs permitted by the chosen workflow. Installation, opening a capsule and reviewing a proposed action do not grant execution, signing or payment authority.
5. **Keep recovery materials separate.** Retain project files, exported artifacts and the SUCCESSOR capsule. Preserve wallet recovery through its own documented process. A capsule is not a wallet backup; restoring project history does not restore permission to run or spend.

The [current Linux manifest](https://github.com/MontrealAI/AGI-Fleet-Linux/releases/download/v1.1.2-qualification/Release-Manifest-v1.1.2.json) and [current Mac manifest](../macos/published-release.json) record each published archive's scope. The Linux and Mac release labels above reflect the published manifests at this documentation checkpoint. A newer source commit does not silently replace those downloads.

## Understand the status before pressing Start

**Published qualification prerelease** means the stated automated checks passed for a particular saved archive. Linux 1.1.2 and Mac 1.20.2 are not production-qualified. Physical installation, live-provider participation, human usability and endurance require their own recorded observations.

**Development preview** means some implementation or acceptance work is unfinished. In Local Skills PR #26, completed assistant and lifecycle components do not complete browser/desktop and native Mac adapters, independent-review placement, protocol/signer integration, cross-host restore fencing or full resource and onboarding behavior. Follow the PR's current acceptance matrix rather than copying an old test total into a release claim.

**Internal checking** is not the same as independently administered review. A second role, process or model does not by itself establish independence. Use the review and eligibility rules of the actual job and workflow.

**STOP, HOLD, blocked or uncertain** means stop and follow the explanation. Do not manually delete a STOP marker, weaken permissions, bypass a readiness check or replay an old grant to make a status appear green.

## Something failed?

Preserve the current state, reports and STOP markers. Open [Linux troubleshooting](TROUBLESHOOTING.md) or [Mac troubleshooting](../macos/docs/TROUBLESHOOTING.md). Record the platform, exact release, role, failed step and visible error code. Share only sanitized diagnostics: never upload a seed phrase, private key, OAuth token, private setup JSON or private work document.

For project recovery, start with the [Builder guide](../successor/docs/GUIDE.md). Import history, inspect the selected version and restore or rerun only through a fresh, explicit authorization. Keep the working version until you deliberately accept a checked improvement.
