Vous + votre aide

Commençons avec le bon Mac.

Sur le Mac qui effectuera le travail, ouvrez menu Apple → À propos de ce Mac.

  • Puce : Apple M1 ou M2. Utilisez les logiciels natifs Apple silicon.
  • macOS : version 15 ou ultérieure.
  • Mémoire : prévoyez 16 Go ou plus. Un Mac de 8 Go n’est pas qualifié.
  • Stockage : prévoyez 40 Go libres, plus l’espace pour les téléchargements et travaux.

Choisissez un Mac dédié, avec une alimentation et une connexion fiables. Gardez-le éveillé, avec la session de travail ouverte pendant les essais. En cas de doute, faites vérifier ces éléments avant de modifier quoi que ce soit.

Avant de continuer

La puce, macOS, la mémoire et le stockage ont été vérifiés. Cette page n’inspecte pas votre ordinateur.

Vous + votre aide

Un téléchargement. Les six rôles.

@@MAC_AVAILABILITY_FR@@ Téléchargez le ZIP Mac Fleet nommé ci-dessous et son fichier de sommes de contrôle, depuis la version officielle.

@@MAC_DOWNLOAD_LABEL_FR@@ ↓Version et sommes de contrôle ↗

ZIP : @@MAC_ASSET_NAME@@
Sommes de contrôle : @@MAC_CHECKSUM_NAME@@

Avant d’ouvrir du code, demandez à votre aide d’ouvrir Terminal, de saisir shasum -a 256 avec une espace à la fin, de glisser le ZIP téléchargé dans la fenêtre, puis d’appuyer sur Retour. Comparez les 64 caractères au résultat publié pour ce fichier.

S’ils correspondent, double-cliquez sur le ZIP. Gardez le dossier extrait complet à un emplacement permanent. Ouvrez START_HERE.html pour le guide hors ligne. Les archives « Source code » de GitHub sont destinées au développement.

Avant de continuer

La somme de contrôle correspond exactement au ZIP, et le dossier complet est extrait. Elle ne remplace pas une signature de développeur Apple.

Administrateur, puis compte de travail

Séparez les approbations et le travail.

Votre administrateur crée deux nouveaux comptes Standard, avec des mots de passe différents, dans Réglages Système → Utilisateurs et groupes :

  • Compte d’approbation (signer) : protège le portefeuille et permet d’approuver les actions.
  • Compte de travail (compute) : exécute les outils d’IA et conserve les connexions au fournisseur. Aucun portefeuille ici.

Ouvrez la session de travail. Utilisez Docker Desktop 4.93.0 pour Apple silicon, avec les outils de ligne de commande User et le contexte Docker de l’utilisateur. L’administrateur peut devoir placer Docker dans Applications; le compte de travail reste Standard. Ouvrez Docker dans ce compte, acceptez vous-même ses conditions, puis attendez que le moteur fonctionne.

Votre aide peut suivre les instructions et la somme de contrôle Docker (anglais). Ne lancez pas Fleet avec sudo.

Avant de continuer

Deux nouveaux comptes Standard existent, et Docker fonctionne dans le compte de travail.

Compte d’approbation · signer

Préparez le rôle choisi.

Ouvrez la session d’approbation, puis le lanceur correspondant dans le dossier Fleet extrait complet.

Agent : ouvrez Launch-AGI-Agent.command. Son dossier est packages/AGI_Agent.

Node : ouvrez Launch-AGI-Node.command. Son dossier est packages/AGI_Node.

Le premier lancement peut préparer un environnement privé vérifié Node 24.21.0. Gardez Internet disponible. Ici, Node désigne le logiciel d’exécution; le rôle Fleet « Node » désigne la vérification du travail.

Pour un nouveau portefeuille, ouvrez le lanceur Seed-Wallet du rôle et choisissez Create wallet. Conservez les 12 ou 24 mots de récupération et l’éventuelle phrase secrète dans vos dossiers privés de récupération. Laissez le portefeuille sans fonds pendant les essais.

Dans le panneau de connexion, choisissez le modèle prévu et Download private setup file (Node : Download my private setup file). Ce fichier relie l’application d’approbation au travailleur.

Avant de continuer

Vous avez le fichier privé JSON du bon rôle. Le portefeuille et ses mots restent dans le compte d’approbation.

Transfert privé → compte de travail

Un seul fichier à transférer.

Transférez uniquement le JSON privé de configuration dans un dossier privé du compte de travail. Un support amovible chiffré peut aider. Copiez-le pendant que vous êtes connecté comme utilisateur de travail, puis éjectez le support.

Dans ce compte, ouvrez Terminal. Saisissez chmod 600 avec une espace à la fin, glissez uniquement le JSON copié dans la fenêtre, puis appuyez sur Retour. Cela limite l’accès au fichier sans afficher son secret.

Ne transférez ni portefeuille, ni mots de récupération, ni dossier complet du compte d’approbation. N’envoyez jamais le JSON à ce site, à GitHub ou dans une conversation d’assistance.

Si les contrôles de propriétaire ou d’accès échouent, consultez le guide de dépannage (anglais) avec votre aide. Gardez l’original inchangé.

Avant de continuer

Le JSON appartient à l’utilisateur de travail et lui seul peut le lire. Le portefeuille reste séparé.

Compte de travail · compute

Suivez les invites, une à une.

  1. Vérifiez que Docker fonctionne dans ce compte de travail.
  2. Ouvrez Install.command dans le dossier Fleet complet ou celui du rôle.
  3. Glissez le JSON privé dans l’invite Terminal en attente, puis appuyez sur Retour.
  4. Lisez la confirmation de séparation des comptes. L’installeur prépare ses environnements privés Node et OpenClaw.
  5. Effectuez les connexions au fournisseur indiquées ci-dessous, dans ce compte.
  6. Examinez le rôle, les autorisations et les limites. Saisissez la phrase APPROVE affichée uniquement si tout correspond à votre intention.
  7. Attendez la disponibilité authentifiée et transaction: complete. Conservez le rapport.

Connexions Agent : Creator, Checker et Reviewer, dans des espaces distincts.

Connexions Node : Checker et Reviewer, dans des espaces distincts.

Les nouveaux profils autorisent jusqu’à 256 exécutions sur 24 heures glissantes et 32 tentatives d’image pour Agent/Node. L’usage du fournisseur peut coûter de l’argent; fixez votre budget avant les essais. Des espaces distincts ne prouvent pas à eux seuls l’indépendance des réviseurs.

Avant de continuer

L’installeur indique transaction: complete avec disponibilité authentifiée. Un port ouvert ne suffit pas.

Compte d’approbation · signer

Examinez le résultat réel.

Revenez à l’application d’approbation. Vérifiez l’identité authentifiée du travailleur et approuvez uniquement le test de connexion limité prévu.

Choisissez Test my connection, puis Create test documents. Téléchargez et ouvrez les fichiers. Vérifiez leur contenu. Vous pouvez ensuite essayer une petite tâche publique dans Studio avec Create & check the work.

Utilisez le parcours de vérification Node avec les données publiques d’origine, les fichiers réellement livrés et des critères d’acceptation explicites. Examinez ses preuves et sa décision. Un résultat Agent ne qualifie pas ce Node.

Confirmez le nettoyage positif des conteneurs de travail et de navigateur, l’enregistrement d’observation et la finalisation de l’espace de travail. Si COMPUTE_STOP apparaît ou si le nettoyage est incertain, conservez l’état arrêté et consultez l’aide ci-dessous.

Avant de continuer

Le résultat ou la vérification a été examiné, et les deux nettoyages sont confirmés. Le site ne peut pas vérifier ces observations.

Vous + un réviseur indépendant

Gardez les preuves et la prochaine étape.

Consignez l’installation initiale, l’isolation Docker, le travail réel du fournisseur, les documents, le nettoyage, l’arrêt et la reprise, puis l’identité après redémarrage dans la liste de qualification physique (anglais). La qualification complète exige aussi 72 heures d’observation ininterrompues et une révision indépendante.

La version vise M1 et M2; qualifier une machine ne qualifie pas l’autre. Chaque rôle nécessite ses propres observations. La signature Apple et la notarisation restent à réaliser.

Gardez les travaux financés et les transactions désactivés jusqu’à l’acceptation des contrôles opérationnels, contractuels et de révision requis. Cocher les étapes du guide n’autorise pas les travaux rémunérés.

Quel compte dois-je utiliser?

L’étiquette au-dessus de chaque étape vous l’indique. L’administrateur prépare les comptes et applications partagées. Le compte Standard d’approbation protège le portefeuille. Le compte Standard de travail exécute Docker et l’IA. Revenez au compte d’approbation pour approuver les actions et examiner les résultats.

macOS refuse d’ouvrir l’application

Cette version n’est ni signée par Apple ni notariée. Vérifiez d’abord le ZIP officiel et sa somme de contrôle. Demandez à votre aide de suivre l’approbation du fichier précis dans Réglages Système → Confidentialité et sécurité. Si elle est indisponible, arrêtez-vous et consultez le guide de dépannage. Ouvrir le dépannage (anglais) ↗

L’installation s’arrête ou le nettoyage échoue

Conservez l’erreur et l’installation arrêtée. Ne supprimez ni COMPUTE_STOP, ni conteneurs, ni profils, ni comptes. Dans le compte de travail existant, ouvrez Repair-Compute.command du rôle et choisissez 1 — Export current sanitized report. Si aucun profil n’existe encore, gardez l’erreur et l’emplacement du rapport. Examinez le rapport avant de le partager; n’envoyez jamais le JSON privé ni les identifiants.
